Автозапуск наконец поднимает обход, а не один Telegram-прокси. Фоновая проверка стратегии перестала быть чёрным ящиком, а tg-ws-proxy обновлён до 1.10.2.

- Запуск вместе с Windows больше не оставляет обход выключенным. Компонент «Zapret» никогда не попадал в список автозапуска: его значение по умолчанию было «нет», а все места, где обход включается, добавляли туда только tg-ws-proxy. В итоге при старте системы поднимался один прокси, кнопка показывала «выключено», и первое нажатие на неё гасило прокси вместо того, чтобы включить обход — приходилось жать дважды
- Список автозапуска чинится сам при первом запуске после обновления, повторно настраивать ничего не нужно
- Если часть компонентов не поднялась, приложение теперь действительно дозапускает отставшие, а не просто обновляет состояние на экране. Раньше «частично запущено» могло висеть до ручного перезапуска
- Видно, чем занят автоподбор стратегии. Раньше проверка шла молча и давала о себе знать только итоговым уведомлением. Теперь под кнопкой питания виден ход: сначала «Проверка стратегии… 3/8», а если текущая стратегия отвалилась — «Подбор 5/27: FAKE TLS AUTO ALT2 — OK». Тот же текст дублируется в подсказку значка в трее, так что происходящее понятно и когда приложение запустилось свёрнутым вместе с Windows
- Итог проверки больше не теряется. Он остаётся на экране на несколько секунд, пишется в журнал вместе с результатом по каждой перебранной конфигурации и сохраняется в настройках — строка «Последняя проверка» под галочкой «Автоподбор стратегии в фоне» показывает, что и когда было выбрано. Полезно, когда проверка отработала сразу после включения компьютера и уведомление прошло мимо
- В уведомлениях и сообщениях вместо технического идентификатора вида `flowseal|general (ALT3).bat` теперь короткое имя стратегии
- TG WS Proxy обновлён с 1.7.2 (в интерфейсе значился как 1.10.0) до 1.10.2, поэтому окно «доступно обновление tg-ws-proxy» больше не появляется сразу после установки. Вместе с этим приезжают исправления апстрима: keepalive-пинги для WebSocket, чтобы соединение не отваливалось по таймауту NAT, перебор доменов Cloudflare-воркеров с учётом неудачных, рабочая ротация лог-файла и актуальные адреса дата-центров Telegram
